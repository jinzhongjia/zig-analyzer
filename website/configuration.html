Editor plugins and configuration

Set up a plugin for your editor, then configure the server: in the editor for yourself, or in zig-analyzer.zon for everyone working on a project.

// Plugins

Every plugin starts the server for .zig and .zon files and needs Zig 0.17.0 or 0.17.1 in PATH (or in the zig.path setting). The VS Code, Neovim, Vim, and Emacs plugins install a release of the server only when you run their install command; Zed downloads one by itself. Each checks the minisign signature and SHA-256 of the release first.

Install

Search for zig-analyzer in the Extensions view, from the Visual Studio Marketplace or Open VSX (VSCodium, Cursor). Then run zig-analyzer: Install Server from the command palette.

Server

The extension runs zig-analyzer.server.path when it is set, else the release installed by Install Server, else zig-analyzer from PATH. Once a day it checks for a newer release and offers to install it (zig-analyzer.server.checkUpdates turns this off).

Settings

Server options are VS Code settings under zig-analyzer., one per option. Only the settings you set are sent to the server.

// settings.json
{
  "zig-analyzer.zig.path": "/usr/local/bin/zig",
  "zig-analyzer.build.args": ["-Dtarget=aarch64-linux"],
  "zig-analyzer.inlay_hints.parameters": false,
  "zig-analyzer.lint.enable": true,
  "zig-analyzer.lint.rules": { "dead_errdefer": false }
}

Settings of the extension itself: zig-analyzer.server.path, server.extraEnv, server.checkUpdates, trace.server (log LSP messages to the output channel), and debug.adapter.

Commands

Click the zig-analyzer status bar item or use the command palette: Restart Server, Install Server, Reload Workspace (rerun build.zig), Run, Debug, and Show Server Status, File Status, Syntax Tree, Module Graph, Packages. Tests of open files appear in the Testing view.

The Zig extension (ziglang.vscode-zig) is not needed. With both enabled, ZLS runs too and both format Zig files; disable the Zig extension. Extension README →

Install

Install both the Zig extension (grammar, highlighting, file types) and the zig-analyzer extension from Zed's extensions page (zed: extensions).

Server

The extension starts lsp.zig-analyzer.binary.path when it is set, else zig-analyzer in PATH, else a release it downloads and verifies. The download setting picks the release ({ "version": "v0.5.0", "optimize": "ReleaseFast" }) or, with false, turns downloads off. Zed is the only integration that updates the server without asking; pin a version to avoid that.

Settings

Put zig-analyzer first and turn ZLS off; server options go in lsp.zig-analyzer.settings. "semantic_tokens": "combined" keeps Zed's highlighting and adds the server's tokens, which pairs with the server's semantic_tokens.mode = .partial.

// settings.json
{
  "languages": {
    "Zig": {
      "language_servers": ["zig-analyzer", "!zls", "..."],
      "semantic_tokens": "combined"
    }
  },
  "lsp": {
    "zig-analyzer": {
      "settings": {
        "build": { "args": ["-Dtarget=aarch64-linux"] },
        "semantic_tokens": { "mode": "partial" },
        "inlay_hints": { "parameters": false }
      }
    }
  }
}

Settings are sent at startup and whenever they change; editor: restart language server restarts the server. Extension README →

Install

Neovim 0.12+. With the built-in vim.pack:

vim.pack.add({ 'https://github.com/jinzhongjia/zig-analyzer.nvim' })
require('zig-analyzer').setup()

Or with lazy.nvim, where opts is passed to setup():

{
  'jinzhongjia/zig-analyzer.nvim',
  ft = 'zig',
  opts = {},
}

Server

:ZigAnalyzer install installs the latest release (:ZigAnalyzer install v0.5.0 ReleaseFast picks one) and restarts the running servers; it needs curl and tar. The plugin runs cmd from setup() when set, else the installed release, else zig-analyzer in PATH. It reports a newer release once per session (check_updates = false turns this off).

Settings

setup() takes any field of vim.lsp.Config; server options go in settings as a Lua table:

require('zig-analyzer').setup({
  -- cmd = { '/path/to/zig-analyzer' },
  settings = {
    build = { args = { '-Dtarget=aarch64-linux' } },
    inlay_hints = { parameters = false },
    semantic_tokens = { mode = 'partial' },
  },
})

Commands

:ZigAnalyzer status, fileStatus, syntaxTree, moduleGraph, reloadWorkspace, restart, install, and checkUpdates. See :help zig-analyzer and :checkhealth zig-analyzer. Plugin repository →

Install

Install the plugin together with yegappan/lsp (Vim 9) or vim-lsp; it registers the server with whichever is loaded. With vim-plug:

call plug#begin()
Plug 'yegappan/lsp'
Plug 'jinzhongjia/zig-analyzer.vim'
call plug#end()

Server

:ZigAnalyzer install installs the latest release (:ZigAnalyzer install v0.5.0 ReleaseFast picks one) and restarts the running server; it needs curl, tar, and sha256sum or shasum, and checks the signature when minisign is installed. The plugin runs g:zig_analyzer_cmd when set, else the installed release, else zig-analyzer from PATH. g:zig_analyzer_check_updates = 0 turns off the update check.

Settings

let g:zig_analyzer_settings = {
      \ 'build': {'args': ['-Dtarget=aarch64-linux']},
      \ 'inlay_hints': {'parameters': v:false},
      \ }

See :help zig_analyzer for the settings and the :ZigAnalyzer subcommands. Plugin repository →

Install

Emacs 29.1+ with zig-mode or zig-ts-mode. The package registers the server with the built-in Eglot and starts it in Zig buffers:

(package-vc-install
 '(zig-analyzer . (:url "https://github.com/jinzhongjia/zig-analyzer.el")))
(require 'zig-analyzer)
(zig-analyzer-mode 1)

Server

M-x zig-analyzer-install-server installs a release (it needs minisign, curl, and tar). The package uses zig-analyzer-executable when set, else the installed release, else zig-analyzer in PATH.

Settings

zig-analyzer-settings is a plist: arrays are vectors, and false is :json-false. Set it before zig-analyzer-mode, or run M-x zig-analyzer-restart after a change.

(setq zig-analyzer-settings
      '(:build (:args ["-Dtarget=aarch64-linux"])
        :inlay_hints (:parameters :json-false)))

Commands

M-x zig-analyzer-status, zig-analyzer-file-status, zig-analyzer-syntax-tree, zig-analyzer-module-graph, zig-analyzer-reload-workspace, zig-analyzer-restart, and zig-analyzer-show-log. Package repository →

Any LSP client works without a plugin. Start zig-analyzer over stdio with no arguments, attach it to .zig and .zon files, use the nearest directory with build.zig or .git as the root, and turn off ZLS so that only one server runs. Settings go in initializationOptions, or in the zig-analyzer section of workspace/configuration. For example, Helix:

# ~/.config/helix/languages.toml
[language-server.zig-analyzer]
command = "zig-analyzer"

[language-server.zig-analyzer.config]
build.args = ["-Dtarget=aarch64-linux"]

[[language]]
name = "zig"
language-servers = ["zig-analyzer"]

Setups for Helix, Sublime Text, Kate, JetBrains IDEs (LSP4IJ), coc.nvim, and plain Neovim or Eglot are in docs/editors.md →

// Editor settings

The server reads its settings from two places: the editor, for yourself, and a project's zig-analyzer.zon, for everyone. Both have the structure of zig-analyzer.default.zon, the reference file that lists every option with its default and what it does.

From the reference file to your editor

The reference is written in ZON. Editors send the same structure as JSON: a nested struct becomes an object, a list becomes an array, and an enum literal such as .partial becomes the string "partial". Options you leave out keep their defaults.

WhereThe option .build = .{ .args = .{"-Dfoo"} }
JSON (any LSP client){ "build": { "args": ["-Dfoo"] } }
VS Code"zig-analyzer.build.args": ["-Dfoo"]
Zed"lsp": { "zig-analyzer": { "settings": { "build": { "args": ["-Dfoo"] } } } }
Neovimsettings = { build = { args = { '-Dfoo' } } }
Vimlet g:zig_analyzer_settings = {'build': {'args': ['-Dfoo']}}
Emacs(setq zig-analyzer-settings '(:build (:args ["-Dfoo"])))
Helixbuild.args = ["-Dfoo"] in [language-server.zig-analyzer.config]

How the server receives them

  • At startup in initializationOptions, and later in the zig-analyzer section of workspace/configuration and workspace/didChangeConfiguration. An outer "zig-analyzer" wrapper is accepted in both.
  • Settings that arrive later replace the current ones; a change of a setting the build uses (such as build.args) restarts the projects; zig.path takes effect after restarting the server.
  • An unknown option, or a value of the wrong type, is reported as a warning; that option keeps its default and the others still apply.

// zig-analyzer.zon

A project can commit its settings, so everyone gets the same build arguments, diagnostics, and checks whatever editor they use.

Create it

  1. Copy zig-analyzer.default.zon from the repository, or start an empty file.
  2. Save it as zig-analyzer.zon in the project root, the directory with build.zig. A nested project (such as an example with its own build.zig) reads its own file.
  3. Keep only the options the project needs, and commit it.
// zig-analyzer.zon
.{
    .build = .{ .args = .{"-Dtarget=aarch64-linux"} },
    .diagnostics = .{ .steps = .{ "check", "test" } },
    .naming = .{
        .enable = true,
        .ignore = .{"SDL_*"},
        .exclude = .{"vendor/*"},
        .rules = .{ .field = false },
    },
    .unused = .{ .enable = true },
    .lint = .{ .enable = true },
    .imports = .{ .derived = .separate, .sort = .name },
}

How it is used

  • zig-analyzer.default.zon is a reference, not a configuration file. The server never reads it from disk; it ships the same text inside the binary for completion and hover in zig-analyzer.zon. Only a file named zig-analyzer.zon in a project root has an effect.
  • The file wins. Every option written in zig-analyzer.zon takes precedence over the same option in each team member's editor. Options it leaves out come from the editor. A copy of the whole reference file therefore pins every project option to its default, which is why you should keep only what you change.
  • Only project options. The options written as fields in the reference file can be set: build.args, diagnostics.steps, diagnostics.compiler, imports, naming, unused, and lint. Those shown in comments marked editor only (zig, inlay_hints, hover, log, ...) are personal; written here they are reported and ignored, and the rest of the file still applies.
  • Paths are relative to the project root. naming.exclude patterns are /-separated paths from the directory of zig-analyzer.zon (from the workspace root in editor settings).
  • Changes apply on save. Saving the file, or changing it on disk (a git pull, say), restarts the project with the new settings. The old results stay until the new build completes.
  • Errors ignore the whole file. A syntax error, a wrong type, or an unknown option is shown at its location, in the file and as a warning, and the whole file is ignored until it is fixed, so a typo never applies half a configuration.
  • The editor helps. In zig-analyzer.zon, completion offers the options and enum values that can be set, and hover shows each option's description from the reference file.

// Troubleshooting

  • A setting does not apply. Check whether the project's zig-analyzer.zon sets it; the file wins over the editor. Check also that the file has no error, since an error ignores the whole file.
  • No compiler diagnostics. Run zig version: projects need 0.17.0 or 0.17.1. Add a check step to build.zig that depends on the compile steps and tests, or set diagnostics.steps.
  • Two servers run. ZLS and zig-analyzer both give diagnostics and formatting; turn ZLS off in the editor or the other Zig extension.
  • Something else. Set log.level to .debug and log.file to a path, and use the plugin's status commands to see what the server knows about the project and the file.
