# Upgrade the LSP protocol version

`src/lsp/types.zig` is generated by `tools/gen_lsp_types.zig` from `tools/metaModel.json`; its
`version` constant is the metaModel's `metaData.version`. Never edit `types.zig` by hand.

## 1. Find the current and target versions

```sh
head -5 tools/metaModel.json          # metaData.version
grep -n 'pub const version' src/lsp/types.zig
```

If the user did not name a target version, use the newest one published and tell them which.

## 2. Fetch the new metaModel

Sources (both official):

- `https://raw.githubusercontent.com/microsoft/language-server-protocol/gh-pages/_specifications/lsp/<major.minor>/metaModel/metaModel.json`
- `https://raw.githubusercontent.com/microsoft/vscode-languageserver-node/<tag or main>/protocol/metaModel.json`

Download into a new empty temporary directory outside the repository, check `metaData.version` is the target, then
copy it over `tools/metaModel.json`. Keep the file as published (no reformatting), so later diffs
against upstream stay readable.

## 3. Regenerate

```sh
zig build gen
git diff --stat
```

`zig build gen` also regenerates other files (builtin data, manifest data). Only
`tools/metaModel.json` and `src/lsp/types.zig` should change; anything else changing means those
inputs drifted and is a separate commit, not part of this upgrade.

If the generator panics with `unexpected metaModel format`, the new metaModel uses a construct the
generator does not handle yet: extend `tools/gen_lsp_types.zig` (the panic prints the offending
node), keeping its output for the existing constructs unchanged.

## 4. Review the generated diff

Read `git diff src/lsp/types.zig` and list for the user:

- removed or renamed types, fields, enum members, and methods;
- fields that changed type or became required;
- new requests, notifications, and capabilities (candidates for new features, not part of this
  upgrade unless asked).

## 5. Adapt the code and verify

```sh
zig build check                      # fix compile errors in server/, ide/, lsp/ caused by the diff
zig fmt --check .
zig build gen && git diff --exit-code src/lsp/types.zig   # generation is reproducible
zig build test-all
zig build test-all -Doptimize=ReleaseSafe
```

Changes in behavior visible to clients (a capability advertised differently, a field now sent or no
longer sent) go into the matching `docs/features/*.md` or `docs/design.md`.

## 6. Commits

Only when the user asks. Split by content:

1. generator changes in `tools/gen_lsp_types.zig`, if any;
2. `tools/metaModel.json` + regenerated `src/lsp/types.zig` together with the code adaptations
   needed to compile (the tree must build at every commit);
3. any new feature built on the new protocol, separately.

The commit message names the old and new versions (`lsp: upgrade the protocol types to LSP 3.x.y`).
