# Changelog

All notable changes to zig-analyzer. Versions follow [Semantic Versioning](https://semver.org/), independent of Zig versions; the section of each version is also the notes of its [GitHub release](https://github.com/jinzhongjia/zig-analyzer/releases). New sections are generated by `zig build changelog` from the labels of the merged pull requests.

## [0.1.2](https://github.com/jinzhongjia/zig-analyzer/releases/tag/v0.1.2) - 2026-11-16

### Features

- Formatting returns one edit per changed region instead of a single edit spanning from the first change to the last, so the cursor, marks, and folds between two changes stay where they are ([#336](https://github.com/jinzhongjia/zig-analyzer/pull/336)).
- Install with Homebrew (`brew install jinzhongjia/tap/zig-analyzer`) or, on Arch Linux, from the AUR (`yay -S zig-analyzer-bin`); both are updated with each release ([#332](https://github.com/jinzhongjia/zig-analyzer/pull/332), [#339](https://github.com/jinzhongjia/zig-analyzer/pull/339)).
- The editor plugins can install the server: `:ZigAnalyzer install` in Neovim and Vim, the "Install Server" command in VS Code, and in Zed a download of the latest release when no `zig-analyzer` is on PATH. Each checks the archive against the release's `SHA256SUMS` and its minisign signature (in Vim, when `minisign` is installed) ([#325](https://github.com/jinzhongjia/zig-analyzer/pull/325), [#326](https://github.com/jinzhongjia/zig-analyzer/pull/326), [#327](https://github.com/jinzhongjia/zig-analyzer/pull/327), [#328](https://github.com/jinzhongjia/zig-analyzer/pull/328), [#335](https://github.com/jinzhongjia/zig-analyzer/pull/335)).
- The inspection commands (status, file status, syntax tree, module graph) show readable, highlighted views in Neovim, Vim, and VS Code instead of raw JSON; in the syntax tree, a line jumps to its range in the source. `zig-analyzer/syntaxTree` also prints the ranges of tokens ([#329](https://github.com/jinzhongjia/zig-analyzer/pull/329), [#330](https://github.com/jinzhongjia/zig-analyzer/pull/330)).

### Fixes

- Hover on a field in the initializer of a type built with `@Struct` (such as `std.enums.EnumFieldStruct`) shows the field and its type ([#331](https://github.com/jinzhongjia/zig-analyzer/pull/331)).
- Neovim: when no server is installed, the "not found" message appears once instead of once per Zig buffer, and no client is started until `:ZigAnalyzer install` ([#340](https://github.com/jinzhongjia/zig-analyzer/pull/340)).

### Performance

- Completion in files with many imports no longer parses the imported files again for their `//!` docs: on `src/server/Server.zig` of this repository, the slowest completion went from 49 ms to 6 ms ([#341](https://github.com/jinzhongjia/zig-analyzer/pull/341)).

## [0.1.1](https://github.com/jinzhongjia/zig-analyzer/releases/tag/v0.1.1) - 2026-11-13

### Features

- Each platform also has a `ReleaseFast` build next to the recommended `ReleaseSafe` one; the README explains which to pick ([#310](https://github.com/jinzhongjia/zig-analyzer/pull/310)).
- The archives and `SHA256SUMS` are signed with minisign; verify them with `minisign.pub` from the repository ([#310](https://github.com/jinzhongjia/zig-analyzer/pull/310)).
- Each archive has a build provenance attestation (`gh attestation verify`), is smoke-tested on its own platform before the release is published, and includes `CHANGELOG.md` ([#311](https://github.com/jinzhongjia/zig-analyzer/pull/311)).

### Fixes

- Files of the Zig installation are no longer compiled on their own when it lies under a workspace folder (such as Homebrew's prefix), which reported "file exists in modules 'std' and 'Build'"; single-file compiles and `builtin.zig` generation no longer write a `.zig-cache` into the standard library or a project directory; in Neovim, the standard library and dependency packages reached by goto definition attach to the running server instead of starting another one; the Vim plugin with yegappan/lsp no longer takes a directory with a `Build.zig` as the root on macOS and Windows ([#323](https://github.com/jinzhongjia/zig-analyzer/pull/323)).
- Unwrapping a C pointer (`.?`, `orelse`, if / while captures) keeps its type, and literals in the arguments of `@Int`, `@Pointer`, `@Fn`, `@Struct`, `@Union`, `@Enum`, and `@Tuple` resolve ([#314](https://github.com/jinzhongjia/zig-analyzer/pull/314)).
- A value that breaks out of an `inline for` gets its type from the iterations that reach the break ([#315](https://github.com/jinzhongjia/zig-analyzer/pull/315)).
- The macOS archives include `zig-analyzer.dSYM`, so a panic prints file and line numbers; keep it next to the executable ([#316](https://github.com/jinzhongjia/zig-analyzer/pull/316)).

### Performance

- Hover and completion in files with many generic instances are faster: the slowest hover on the Zig compiler's `src/Sema.zig` went from 16 s to 11.5 s, and the slowest completion from 6 s to 1.8 s ([#320](https://github.com/jinzhongjia/zig-analyzer/pull/320)).
- Large projects load faster, and the first workspace symbol search after loading takes milliseconds instead of hundreds: on the Zig compiler source, loading takes 2 s instead of 3.5 s ([#321](https://github.com/jinzhongjia/zig-analyzer/pull/321)).

## [0.1.0](https://github.com/jinzhongjia/zig-analyzer/releases/tag/v0.1.0) - 2026-11-11

The first release of zig-analyzer, a language server for Zig built on an incremental query engine. Supports Zig 0.17.0 and 0.17.1.

### Features

- **Diagnostics** come only from Zig itself: in-process AstGen while typing, and `zig build` over the build system protocol on save. Files without `build.zig` are compiled in single-file mode. Inactive code can optionally be marked.
- **Comptime evaluation**: generics and type constructors are evaluated, and generic function bodies are analyzed with the instances from their call sites.
- **Build system integration**: the project model comes from `zig build --listen=-`, including dependency packages, generated files, and sub-projects that depend on the root by `.path`.
- **Navigation**: goto definition / declaration / type definition, find references, document highlight, document and workspace symbols.
- **Editing**: completion with auto-import and snippets, hover, signature help, inlay hints, and semantic tokens.
- **Refactoring**: rename, and code actions for unused names, parameters, and captures, `var` to `const`, missing switch prongs and struct fields, extracting constants, converting string literals, and organizing imports.
- **Formatting** identical to `zig fmt`, for `.zig` and `.zon`.
- **ZON files**: highlighting, formatting, and diagnostics in any `.zon` file; completion, goto, and inlay hints for files imported with a result type and for `build.zig.zon`; completion and option descriptions in `zig-analyzer.zon`.
- **Structure**: folding ranges and selection ranges.
- **Naming checks** (opt-in), based on the Names section of the Zig style guide, with safe rename fixes.
