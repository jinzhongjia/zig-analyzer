# Changelog

All notable changes to zig-analyzer. Versions follow [Semantic Versioning](https://semver.org/), independent of Zig versions; the section of each version is also the notes of its [GitHub release](https://github.com/jinzhongjia/zig-analyzer/releases). New sections are generated by `zig build changelog` from the labels of the merged pull requests.

## [0.5.1](https://github.com/jinzhongjia/zig-analyzer/releases/tag/v0.5.1) - 2026-11-27

### Features

- Hover on a function returning `!T` lists the members of its inferred error set after the signature (`` errors: `error{A,B}` ``), as the compiler computes them; it is omitted when the members depend on an instance or cannot be determined exactly ([#570](https://github.com/jinzhongjia/zig-analyzer/pull/570)).
- Arch Linux users can install the AUR package `zig-analyzer`, which builds the release from source with Arch Linux's `zig`, besides the prebuilt `zig-analyzer-bin` ([#568](https://github.com/jinzhongjia/zig-analyzer/pull/568)).

### Performance compared with v0.5.0

Linux x86_64, 16 CPUs (Intel Core Ultra 7 255H), ReleaseSafe, Zig 0.17.1, on the Zig 0.17.1 compiler source: the full run on `src/Sema.zig` (3 rounds per version) and find references on 40 declarations of `src/Sema.zig` (2 rounds) and `src/Zcu.zig` (4 rounds), alternating between the versions.

- Resident memory at the end of the full run: 548–557 MB with v0.5.0, 550–558 MB with v0.5.1.
- Startup, opening a file, hover, goto, completion, edit → diagnostics, semantic tokens, and find references are unchanged within noise.

## [0.5.0](https://github.com/jinzhongjia/zig-analyzer/releases/tag/v0.5.0) - 2026-11-24

### Features

- Completion offers postfix items after `.` on a value: `.*` on a pointer, `.?` on an optional, and with snippets `.try` (inserts `try` before the expression where the function's error set allows it) and `.catch` (a `catch |err| switch (err)` with a prong per known error); expressions and type positions also offer `true` / `false` / `null` / `undefined` and the primitive types, ranked by the expected type. The new setting `completion.call_snippets` (default `true`) makes functions and builtins insert only their name when off ([#555](https://github.com/jinzhongjia/zig-analyzer/pull/555)).

### Fixes

- A decl literal of a declaration without `pub` in another file (`const x: a.S = .secret;`) no longer resolves, matching the compiler, and an enum literal coerced to a type that takes none (`const s: S = .name;`) no longer shows a value ([#554](https://github.com/jinzhongjia/zig-analyzer/pull/554)).

### Performance

- Find references and rename of a declaration without `pub` search only its own file (a project with 200 files importing it: 35.9 ms → 0.1 ms), and a syntax error or an unconfirmable member access in another file no longer makes such a rename refuse ([#556](https://github.com/jinzhongjia/zig-analyzer/pull/556)).
- Find references and rename resolve each file's imports once instead of on every request (references p50 on `Server.zig`: 3.7 ms → 1.2–1.5 ms), and rename checks string literals from a per-file index instead of parsing every candidate file (1000 unopened files: 68.6 ms → 0.08 ms) ([#561](https://github.com/jinzhongjia/zig-analyzer/pull/561), [#557](https://github.com/jinzhongjia/zig-analyzer/pull/557)).
- Typing in large files does less per keystroke: the edit range is found with vector compares (5–12× faster), the parse shares the document text instead of copying it (a ~1 MB file: about 1.4 ms → 0.85 ms per keystroke, half the page faults), and syntax walks skip subtrees without nested containers or imports (a body edit in a 30k-node member: 1.35 ms → 0.26 ms) ([#564](https://github.com/jinzhongjia/zig-analyzer/pull/564), [#563](https://github.com/jinzhongjia/zig-analyzer/pull/563)).
- Responses are written to the client after the request's read lock is released, and formatting and code actions compute outside it, so a large response, a slow client, or formatting a large file no longer holds up the next edit ([#559](https://github.com/jinzhongjia/zig-analyzer/pull/559)).
- Compiler diagnostics diff each pair of texts once per publish instead of once per note (20 errors with notes: 41 diffs → 1) and reuse the AstGen result live diagnostics already computed (25–30 ms → 0.2–0.3 ms per errored file per build) ([#562](https://github.com/jinzhongjia/zig-analyzer/pull/562)).
- `workspace/symbol` builds only the symbols it returns (100k matches: about 7 ms → 1.5 ms), and smaller costs are removed from hover, inlay hints, completion, document symbols, diagnostics publishing, the name index, and the query engine ([#560](https://github.com/jinzhongjia/zig-analyzer/pull/560), [#558](https://github.com/jinzhongjia/zig-analyzer/pull/558)).

## [0.4.1](https://github.com/jinzhongjia/zig-analyzer/releases/tag/v0.4.1) - 2026-11-23

### Fixes

- Progress notifications are sent without holding the workspace lock, so a client that stops reading the server's output during a large build no longer freezes publishing, origin rules, and requests ([#537](https://github.com/jinzhongjia/zig-analyzer/pull/537)).
- A project load that fails frees the project model and the file texts it read instead of leaking them ([#523](https://github.com/jinzhongjia/zig-analyzer/pull/523)).

### Performance

- Live diagnostics repeat less work per publish: the origin rules and file context are computed once instead of five times, the standard library closure is reused across compile steps (a synthetic graph of 1000 steps: 504 ms → 58 ms), each builtin is read once per module graph update, and the builtin documentation for `@` completion is looked up without allocating ([#527](https://github.com/jinzhongjia/zig-analyzer/pull/527), [#524](https://github.com/jinzhongjia/zig-analyzer/pull/524), [#525](https://github.com/jinzhongjia/zig-analyzer/pull/525), [#526](https://github.com/jinzhongjia/zig-analyzer/pull/526)).
- Cursor requests, find references, and rename build the import graph once per request (an error-name rename built it three or more times), cache each file's URI for the request, check the item Bloom filter before building member nodes, scan the AstId map directly in `ownerAt`, and compute auto-import names once per request ([#529](https://github.com/jinzhongjia/zig-analyzer/pull/529), [#536](https://github.com/jinzhongjia/zig-analyzer/pull/536), [#518](https://github.com/jinzhongjia/zig-analyzer/pull/518), [#521](https://github.com/jinzhongjia/zig-analyzer/pull/521), [#522](https://github.com/jinzhongjia/zig-analyzer/pull/522)).
- Edits and large file-watch batches hold the main loop for less time: an incremental reparse computes the edit range once (a top-level edit of `Sema.zig` compares ~3 MB fewer bytes per keystroke), and watched files are read and hashed before the write lock, so a large `git checkout` no longer blocks requests and edits while the files are read ([#530](https://github.com/jinzhongjia/zig-analyzer/pull/530), [#531](https://github.com/jinzhongjia/zig-analyzer/pull/531)).
- Hover, completion, and inference allocate and scan less: signature results are sized to the signature prefix, field pointer attributes skip the types of the other fields, container arguments are read only when needed, outer `comptime var` writes are collected once per inference, and error sets of 0–1 names skip sorting and allocation ([#532](https://github.com/jinzhongjia/zig-analyzer/pull/532), [#533](https://github.com/jinzhongjia/zig-analyzer/pull/533), [#535](https://github.com/jinzhongjia/zig-analyzer/pull/535), [#516](https://github.com/jinzhongjia/zig-analyzer/pull/516)).
- The database no longer contends on one global access counter, releases a frame's pins with one lock per table instead of one per read, and selects the read-eviction prefix without sorting or allocating multi-MB arrays under the table lock ([#519](https://github.com/jinzhongjia/zig-analyzer/pull/519), [#520](https://github.com/jinzhongjia/zig-analyzer/pull/520), [#534](https://github.com/jinzhongjia/zig-analyzer/pull/534)).
- The slow-request trace is recorded only when the report is enabled (the largest hover no longer builds ~53 MB of trace events when it is off), and the report sums self time in one pass ([#528](https://github.com/jinzhongjia/zig-analyzer/pull/528)).

## [0.4.0](https://github.com/jinzhongjia/zig-analyzer/releases/tag/v0.4.0) - 2026-11-22

### Features

- Completion offers Zig keywords where the syntax admits them: container members, statements, expressions, types, pointer attributes, and parameters; `return`, `break`, and `continue` only where they are valid ([#485](https://github.com/jinzhongjia/zig-analyzer/pull/485)).
- With nothing typed, name completion ranks the candidates that fit the expected type first (after `=`, `return`, in call arguments, `.f =`, `orelse`, `catch`, switch prongs, and more) ([#490](https://github.com/jinzhongjia/zig-analyzer/pull/490)).
- `@import` of a dependency in build.zig resolves once `zig build` has fetched it, without restarting; an import of a dependency that is not fetched gets the `build.unfetched_dependency` warning with a quick fix that runs `zig build --fetch` ([#491](https://github.com/jinzhongjia/zig-analyzer/pull/491)).
- Hover and completion on a re-export (`const f = other.f;`) show the doc comment of the aliased declaration when the alias has none ([#486](https://github.com/jinzhongjia/zig-analyzer/pull/486)).
- The status views of VS Code, Neovim, and Vim show how many incomplete results were caused by an external tool that could not run ([#481](https://github.com/jinzhongjia/zig-analyzer/pull/481)).

### Fixes

- Completion offers no names from scope where no name reference can stand: declaration, parameter, field, capture, and label names, error set definitions, numbers, and operators ([#492](https://github.com/jinzhongjia/zig-analyzer/pull/492)).
- Live diagnostics that could not run (zig not started, crashed, or timed out) are checked again on the next read instead of staying empty until the file is edited ([#472](https://github.com/jinzhongjia/zig-analyzer/pull/472)).
- Rename, remove parameter, and remove unused capture refuse the edit when the AstGen check of the edited text could not run, instead of treating it as passed ([#483](https://github.com/jinzhongjia/zig-analyzer/pull/483)).

## [0.3.0](https://github.com/jinzhongjia/zig-analyzer/releases/tag/v0.3.0) - 2026-11-20

### Breaking changes

- Hover on a member name in a generic function body now shows only how many other declarations it refers to under other instances (`hover.instances = "count"`, the new default); go to definition lists them. `"list"` is replaced by `"count"`, and `"full"` still shows each declaration's location and complete hover ([#372](https://github.com/jinzhongjia/zig-analyzer/pull/372)).

### Features

- Hover shows the size and alignment of a type (`size: 8 · align: 4`) and the byte offset of a struct field when the layout is fully known; turn it off with `hover.layout` ([#467](https://github.com/jinzhongjia/zig-analyzer/pull/467)).
- Lint hints (opt-in, `lint.enable`): redundant `@as` / `@intCast` / `@truncate` / `@floatCast`, integer comparisons with a literal that the type decides, and `errdefer` that never runs; `lint.rules` turns each rule on or off ([#468](https://github.com/jinzhongjia/zig-analyzer/pull/468)).
- Type inlay hints for captures (`|x|`, `|*p|`, `|v, i|`, `|err|`), set by `inlay_hints.capture_types` ([#464](https://github.com/jinzhongjia/zig-analyzer/pull/464)).
- Hover can show the compiler's fully qualified name of a container-level declaration (`fqn: main.Wide`, opt-in `hover.fqn`) ([#465](https://github.com/jinzhongjia/zig-analyzer/pull/465)).
- The status views of VS Code, Neovim, and Vim show the running server version, and `zig-analyzer/status` reports it in `version` ([#369](https://github.com/jinzhongjia/zig-analyzer/pull/369)).
- The Emacs package installs with `package-vc-install` from the read-only mirror `jinzhongjia/zig-analyzer.el` ([#366](https://github.com/jinzhongjia/zig-analyzer/pull/366)).

### Fixes

- The first completion after opening a file includes auto-import candidates; the import index starts when the first Zig document opens ([#466](https://github.com/jinzhongjia/zig-analyzer/pull/466)).
- `defer` and `errdefer` bodies are inferred at each exit of their block that runs them, once per iteration in `inline` loops, and hover shows the declaration at each exit ([#423](https://github.com/jinzhongjia/zig-analyzer/pull/423), [#458](https://github.com/jinzhongjia/zig-analyzer/pull/458), [#461](https://github.com/jinzhongjia/zig-analyzer/pull/461), [#462](https://github.com/jinzhongjia/zig-analyzer/pull/462)).
- Comptime evaluation matches the compiler in more cases: writing the active field of a comptime union, slicing comptime-known slices and concatenating them with `++`, tuple ++ array, signed division and `%`, unary operators on vectors, calls through function pointers, `@ptrFromInt` and address comparison, sentinel stores and explicit slice sentinels, sentinels through frozen many-item pointers, `len` of a slice from an array pointer, `c_longdouble` at the target's width, integer/float peer types, optionals across representations, null pointers in optionals, destructures into `comptime var`, and the size of `?noreturn` ([#424](https://github.com/jinzhongjia/zig-analyzer/pull/424), [#425](https://github.com/jinzhongjia/zig-analyzer/pull/425), [#426](https://github.com/jinzhongjia/zig-analyzer/pull/426), [#427](https://github.com/jinzhongjia/zig-analyzer/pull/427), [#428](https://github.com/jinzhongjia/zig-analyzer/pull/428), [#429](https://github.com/jinzhongjia/zig-analyzer/pull/429), [#430](https://github.com/jinzhongjia/zig-analyzer/pull/430), [#431](https://github.com/jinzhongjia/zig-analyzer/pull/431), [#432](https://github.com/jinzhongjia/zig-analyzer/pull/432), [#433](https://github.com/jinzhongjia/zig-analyzer/pull/433), [#434](https://github.com/jinzhongjia/zig-analyzer/pull/434), [#435](https://github.com/jinzhongjia/zig-analyzer/pull/435), [#436](https://github.com/jinzhongjia/zig-analyzer/pull/436), [#437](https://github.com/jinzhongjia/zig-analyzer/pull/437), [#451](https://github.com/jinzhongjia/zig-analyzer/pull/451), [#456](https://github.com/jinzhongjia/zig-analyzer/pull/456), [#457](https://github.com/jinzhongjia/zig-analyzer/pull/457)).
- Code the compiler rejects gets no value or type in hover and inlay hints (signed `%`, inexact float coercion, stores through `const`, invalid vector element types and `@reduce` / `@select` / `@shuffle` operands, `@hasDecl` on a non-container, invalid reified containers) ([#455](https://github.com/jinzhongjia/zig-analyzer/pull/455)).
- Syntax errors for capture, chained comparison, `align` bit range, and `inline var` forms the compiler rejects, at the compiler's position and message ([#454](https://github.com/jinzhongjia/zig-analyzer/pull/454)).
- Each anonymous struct literal has a type of its own, so `@TypeOf(x) == @TypeOf(y)` of two equal-looking literals is `false` as in the compiler; anonymous containers render with their tag type, layout, and backing integer ([#420](https://github.com/jinzhongjia/zig-analyzer/pull/420), [#452](https://github.com/jinzhongjia/zig-analyzer/pull/452)).
- Name resolution follows the compiler: non-`pub` members of another file do not resolve, imports leaving the module root are not followed, and `const x = x;` at container level does not resolve to itself ([#445](https://github.com/jinzhongjia/zig-analyzer/pull/445), [#442](https://github.com/jinzhongjia/zig-analyzer/pull/442), [#443](https://github.com/jinzhongjia/zig-analyzer/pull/443)).
- Hover and goto work at member calls on abstract parameters in branches inactive for the current target ([#375](https://github.com/jinzhongjia/zig-analyzer/pull/375)).
- Rename refuses multiline and escaped string keys, updates `@field` strings in every file the reference search covers, and is refused for `.zon` fields when not all instances were explored ([#447](https://github.com/jinzhongjia/zig-analyzer/pull/447), [#446](https://github.com/jinzhongjia/zig-analyzer/pull/446), [#448](https://github.com/jinzhongjia/zig-analyzer/pull/448)).
- Completion offers quoted error names (`error.@"..."`), paths in `@import` with the string on the next line, no more union fields after one is assigned, and auto-imports of files shared by several modules ([#449](https://github.com/jinzhongjia/zig-analyzer/pull/449), [#444](https://github.com/jinzhongjia/zig-analyzer/pull/444), [#441](https://github.com/jinzhongjia/zig-analyzer/pull/441)).
- The outline gives functions and declarations the same kind as semantic highlighting ([#440](https://github.com/jinzhongjia/zig-analyzer/pull/440)).
- Builtin hover text for `@bitSizeOf`, `@sizeOf`, `@errorName`, and `@tagName` matches the compiler ([#439](https://github.com/jinzhongjia/zig-analyzer/pull/439)).
- View tables in the editor plugins left-align text columns ([#367](https://github.com/jinzhongjia/zig-analyzer/pull/367)).

## [0.2.0](https://github.com/jinzhongjia/zig-analyzer/releases/tag/v0.2.0) - 2026-11-17

### Features

- Goto definition on an `@import` alias opens the imported file instead of the declaration that imports it, through any chain of aliases (`const other = @import("other.zig")`, `std.mem.Allocator`) ([#357](https://github.com/jinzhongjia/zig-analyzer/pull/357)).
- Unused declarations (opt-in, `unused.enable`): hints on private `fn`, `const` and `var` declarations that no code in the same file reaches, including helpers used only by another unused declaration; `@field` and `@hasDecl` with a string literal keep the declaration alive ([#350](https://github.com/jinzhongjia/zig-analyzer/pull/350)).
- `// zig-analyzer-disable`, `// zig-analyzer-enable`, and `// zig-analyzer-disable-next-line` comments suppress analyzer hints for a range or a line, all of them or the named ones (`naming`, `unused`, `inactive`); diagnostics from the compiler are never suppressed ([#350](https://github.com/jinzhongjia/zig-analyzer/pull/350)).
- Completion offers snippets for common statements and declarations: `if` with an optional capture or an error union, `for` over a range and `inline for`, `while` with a capture and a continue expression, `defer`, `errdefer`, `try`, `const` / `var`, `packed` and `extern` structs, `enum(u8)`, `union(enum)`, `comptime` blocks, and `std.debug.assert` / the `std.testing` checks where `std` is the standard library ([#348](https://github.com/jinzhongjia/zig-analyzer/pull/348)).

### Fixes

- In a file that belongs to several modules importing different files under one name, goto, references, and rename treat a member path past such an import (`cfg.sub.value`) in every module instead of only the highest-priority one ([#358](https://github.com/jinzhongjia/zig-analyzer/pull/358)).

### Performance

- Completion while typing recomputes only what an edit touches in the syntax layer and the bodies: on the Zig compiler's `Sema.zig`, p50 went from 157 ms to 79 ms with auto-import on, and from 59 ms to 29 ms with it off ([#354](https://github.com/jinzhongjia/zig-analyzer/pull/354)).
- The reverse import graph is shared between searches, a top-level edit reparses only up to the first member after it, and ItemTree lookups use tables: the slowest hover on the Zig compiler's source went from 22.0 s to 17.1 s, a top-level edit of `Sema.zig` from 20.5 ms to 1.7 ms, and semantic tokens delta p50 from 229 ms to 148 ms ([#353](https://github.com/jinzhongjia/zig-analyzer/pull/353)).
- Auto-import indexes the workspace files outside every module too, so completion in a file in no module no longer computes import sites in the request: the second completion on `Sema.zig` went from 1211 ms to 700 ms ([#359](https://github.com/jinzhongjia/zig-analyzer/pull/359)).

## [0.1.1](https://github.com/jinzhongjia/zig-analyzer/releases/tag/v0.1.1) - 2026-11-13

### Features

- Each platform also has a `ReleaseFast` build next to the recommended `ReleaseSafe` one; the README explains which to pick ([#310](https://github.com/jinzhongjia/zig-analyzer/pull/310)).
- The archives and `SHA256SUMS` are signed with minisign; verify them with `minisign.pub` from the repository ([#310](https://github.com/jinzhongjia/zig-analyzer/pull/310)).

- The macOS archives include `zig-analyzer.dSYM`, so a panic prints file and line numbers; keep it next to the executable ([#316](https://github.com/jinzhongjia/zig-analyzer/pull/316)).

### Performance

- Hover and completion in files with many generic instances are faster: the slowest hover on the Zig compiler's `src/Sema.zig` went from 16 s to 11.5 s, and the slowest completion from 6 s to 1.8 s ([#320](https://github.com/jinzhongjia/zig-analyzer/pull/320)).
- Large projects load faster, and the first workspace symbol search after loading takes milliseconds instead of hundreds: on the Zig compiler source, loading takes 2 s instead of 3.5 s ([#321](https://github.com/jinzhongjia/zig-analyzer/pull/321)).

## [0.1.0](https://github.com/jinzhongjia/zig-analyzer/releases/tag/v0.1.0) - 2026-11-11

The first release of zig-analyzer, a language server for Zig built on an incremental query engine. Supports Zig 0.17.0 and 0.17.1.

### Features

- **Diagnostics** come only from Zig itself: in-process AstGen while typing, and `zig build` over the build system protocol on save. Files without `build.zig` are compiled in single-file mode. Inactive code can optionally be marked.
- **Comptime evaluation**: generics and type constructors are evaluated, and generic function bodies are analyzed with the instances from their call sites.
- **Build system integration**: the project model comes from `zig build --listen=-`, including dependency packages, generated files, and sub-projects that depend on the root by `.path`.
- **Navigation**: goto definition / declaration / type definition, find references, document highlight, document and workspace symbols.
- **Editing**: completion with auto-import and snippets, hover, signature help, inlay hints, and semantic tokens.
- **Refactoring**: rename, and code actions for unused names, parameters, and captures, `var` to `const`, missing switch prongs and struct fields, extracting constants, converting string literals, and organizing imports.
- **Formatting** identical to `zig fmt`, for `.zig` and `.zon`.
- **ZON files**: highlighting, formatting, and diagnostics in any `.zon` file; completion, goto, and inlay hints for files imported with a result type and for `build.zig.zon`; completion and option descriptions in `zig-analyzer.zon`.
- **Structure**: folding ranges and selection ranges.
- **Naming checks** (opt-in), based on the Names section of the Zig style guide, with safe rename fixes.
